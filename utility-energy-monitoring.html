01 / Technical starting point

Before the dashboard, define what the meter means.

A meter may cover more than one process or include ancillary loads. Steam, water, compressed air and electricity can cross physical and reporting boundaries. The first job is to map the source, units, sampling and intended attribution before comparing areas or product runs.

Explore our engineering phases

02 / Technical considerations

What the application has to address.

Typical scoping questions. The answers shape the scope, deliverables and acceptance criteria for your project.

01

Meter and source audit

Record meter type, location, scaling, units, timestamp quality, ownership and areas served.

02

Production context

Connect consumption to batch, campaign, asset, shift, product, throughput or operating state where source data permits.

03

Views for investigation

Explore demand and time trends, period summaries or resource-per-output views when the normalization basis is valid.

04

Engineering follow-through

Use findings to identify where process review, maintenance, metering, setpoint or control changes warrant further evaluation.

✳

Every project requires a defined technical owner, acceptance basis and a scope proportionate to its operating context.

03 / Scope logic

From an engineering question to an operating system.

The aim is to distinguish what is known, what must be engineered and what evidence is needed next.

01 / APPLICATION LAYER

Measure

Define the relevant boundary and check existing data quality.

02 / APPLICATION LAYER

Contextualize

Join selected resource readings with operating and production information.

03 / APPLICATION LAYER

Investigate

Separate observed changes from proven root causes and prioritize engineering action.

04 / Delivery sequence

A practical path toward the next decision.

  1. 01Identify one resource and the business question
  2. 02Map meters, limits and source-quality gaps
  3. 03Connect only the necessary process context
  4. 04Review trends and validate suspected drivers

Contract stages remain separate. Progression from Basic Engineering & Feasibility to Detailed Engineering or Integrated Design & Build is not automatic.

05 / First conversation

Start with the evidence already available.

A useful first discussion is about the existing basis, the technical uncertainty and the milestone it affects. A complete specification is not required to start clarifying the scope.

Prepare a technical enquiry
Useful inputs to bring
  • Utility type and existing metering inventory
  • Relevant process, area or equipment boundaries
  • Production/batch reporting and shift data
  • Current bill, dashboard or known utility concern

06 / Common questions

Decisions worth clarifying.

Must all meters be replaced before a monitoring project starts?

No. First determine what is already available and whether the measurements answer the intended question.

Will a dashboard automatically deliver savings?

No. Monitoring can reveal opportunities, but engineering assessment and implemented changes are needed to demonstrate a particular outcome.
